# 跨境选品全流程（AI 执行版）— 用户提供的原文（2026-10-23）

> 来源：用户整理的 13 步选品流程。本文件是**原文存档**，供 skill `.claude/skills/amazon-sourcing-jp/` 引用。
> 以 Amazon 跨境选品为主，"K帕" = Keepa。文中数字均为演算示例，不代表真实类目。

## 目的

确认一个商品是否同时具备五个条件：有持续需求、有可以进入的竞争位置、有值得顾客购买的改进、扣除完整成本后有利润，以及支撑判断的数据可信。这些条件相互验证：搜索量证明有人关注，销量证明有人购买，评论揭示购买后的体验，价格决定顾客愿意付多少钱，退货决定收入最终能保留多少，历史数据检查眼前表现是否持续。13 步按顺序分析，也需要根据后面的发现返回前面重新计算。

## 开始之前：统一数据口径

| 项目 | 必须写清楚的内容 |
|---|---|
| 目标市场 | 哪个平台、哪个国家站点 |
| 商品边界 | 哪类顾客、什么使用场景、什么具体产品 |
| 时间窗口 | 近30天、自然月、近90天还是全年 |
| 商品层级 | 单个子ASIN、整个产品族，还是多个商品的合计 |
| 数值性质 | 实际记录、平台指标、第三方估算、情景假设或未知 |
| 样本定义 | 类目榜前20、自然搜索前20，还是估算销量前20 |
| 成本口径 | 币种、汇率、含税或不含税、费用是否重复计算 |

Top20 默认指：同一细分需求中，经过相关性筛选和产品族去重，再按同口径月销量排列的 20 个直接竞品。采用「类目 BSR 前 20」或「关键词自然搜索前 20」时要明确标注，BSR 与关键词排名不能混用。

**硬性要求：没有取得的数据写「未知」；估算值明确写「估算」；不能为了完成表格而编造数值。**

## 第一步：核心关键词月搜索量

回答：目标顾客是否主动寻找这个商品，搜索意图是否与准备出售的产品一致。

先定义产品再定关键词（「收纳箱」宽，「汽车后备箱折叠收纳箱」接近购买场景）。关键词分：核心品类词 / 功能词 / 场景词 / 规格词 / 品牌词 / 配件或信息词。逐词记录搜索量、统计周期、来源、购买意图，剔除无关流量。

搜索量 = 指定期间某查询被搜索的次数（Amazon SQP 定义）。月搜 1 万 ≠ 1 万独立顾客 ≠ 1 万订单；多词相加不是去重买家数。

判断：① 搜索意图是否准确 ② 需求是否分布在多个有效词 ③ 是否过度依赖某大品牌词 ④ 趋势是否持续 ⑤ 可承担获客成本下有没有足够成交机会。不设统一「超过一万就能做」门槛。

**输出**：核心关键词表、需求趋势、无关流量说明、需求是否足以继续研究。

## 第二步：类目前 20 的月销量中位数

回答：主要竞品群体通常卖到什么规模，是否被少数爆款拉高。

先核对 20 个商品可比性（用途、规格、套装数、目标顾客、销售状态）。同一产品多颜色不算多个对手；父体总销量不能重复填入各子体。

月销量中位数 = 第 10 个与第 11 个销量之和 ÷ 2。

示例（虚构）：100、120、140、150、180、200、230、250、280、300、340、380、420、450、500、600、700、900、1500、5000 → 合计 12,740、平均 637、中位数 320。5000 的头部拉高了平均值。

Top20 中位数 320 ≠ 新品能卖 320。Top20 已是表现好的样本；估新进入者机会要补看近期进入、低销量、更广可比范围。BSR 是相对排名，不能直接读作月订单；第三方按 BSR 推算的销量必须标「估算」。

**输出**：有效样本数、中位数、平均数、销量分布、异常商品、样本不能代表什么。

## 第三步：季节曲线

回答：需求全年持续还是集中在季节/节日/促销。

至少看完整一年，条件允许用 24–36 个月比同季重复性。同时看：核心词搜索变化、多个可比商品销量/排名、正常价与促销价、库存供货、大促节日事件。销量突降先确认是否缺货。

月度需求指数 = 该月日均搜索量 ÷ 全年日均搜索量。
旺季集中度 = 销量最高 3 个月之和 ÷ 全年销量。

Google Trends 的 0–100 是归一化兴趣，不是 Amazon 搜索量或销量。把曲线转成备货：生产、质检、运输、入仓各需多久，货到时处于旺季前段还是尾声。

**输出**：淡旺季月份、年度重复证据、促销影响、建议上市窗口、错过窗口的库存风险。

## 第四步：评论数 ÷ 月销量

回答：已有评价积累相对近期销量处于什么水平；新品是否有机会在评价少时获得销售。

先明确「评论数」是评分数还是带文字评论数。
累计评价销量比 = 当前累计评价数 ÷ 近 30 天估算销量。示例：A 300/1500=0.2，B 3000/1500=2。

**这个比值不是留评率**（分子累计多年，分母只 30 天）。不能据此单独判断进入难易、销量真实、刷单、顾客是否愿评价。
补充：90 天评价增量与销量比 = 90 天新增评价 ÷ 同期估算销量（仍受滞后、删除、变体共享、估算误差影响）。

**输出**：比值分布、商品年龄、近期评价变化、低评价持续销售的候选商品。

## 第五步：头部集中度

回答：销量分布在多个竞争者，还是集中在少数商品/品牌。

| 类型 | 对象 |
|---|---|
| 产品集中度 | 少数商品 |
| 品牌集中度 | 少数品牌（先按品牌归并） |
| 卖家集中度 | 少数销售主体 |

CR3 = 前三名之和 ÷ Top20 总销量。示例产品 CR3 =（5000+1500+900）÷12740 ≈ 58.1%（产品集中度，无品牌映射不能称品牌集中度）。只研究 Top20 时写「Top20 样本内占比」，不是全类目份额。解释头部为何领先：品牌、功能、成本、内容、服务、临时促销。高集中需更强进入理由；低集中可能伴随同质化价格战。

**输出**：产品与品牌集中度、头部优势、新进入者表现、拟进入细分位置。

## 第六步：自营占比

回答：Amazon 是否作为销售方长期参与，对价格和购买入口的影响。

区分：Amazon 作为销售方 / Amazon 配送 / FBA 履约 / Amazon 自有品牌。**FBA 第三方不算自营。**
输出三项：① 自营报价覆盖率 = Top20 中有自营在售报价的产品数 ÷ 有效样本数 ② 自营获得 Buy Box 的持续性 ③ 自营实际销量份额（无可归属数据则写未知）。一个 ASIN 同时有 Amazon 和他卖家报价，不能全归 Amazon。Keepa 的 Buy Box 赢得比例是获得购买入口的时间比例（非 Prime 口径），不是销量份额。

**输出**：自营参与程度、历史持续性、价格约束、第三方仍能获得销售的证据。

## 第七步：毛利率与真正留下的贡献

回答：扣除完整成本每件留下多少钱。

先统一币种、规格、期间、税务口径，分三层：

| 层级 | 计算 |
|---|---|
| 商品毛利 | 销售收入 − 到仓成本 |
| 履约后广告前贡献 | 再扣平台费、履约物流、仓储及其他订单成本 |
| 广告和退货后贡献 | 再计获客支出及退货退款影响 |

到仓成本逐项：采购、包装、头程、税费；再查优惠活动费、滞销处置、售后。平台费按站点、实际尺寸重量、当时规则（费用模拟器是估算，不含所有费用）。
「贡献」≠ 净利润（未扣固定费用与所得税）。
盈亏平衡月销量 = 每月固定费用 ÷ 每件广告退货后贡献（示例 300,000÷600=500 件）。单位贡献为负时扩大销量无法解决亏损。
每单可承担广告费 = 退货调整后的广告前预期贡献 − 目标每单贡献。
压力测试：售价 −10%、广告 +30%、退货率 +5pt；不要把最乐观销量、最高价、最低成本拼在一起。

**输出**：成本明细、单位贡献、盈亏平衡销量、可承受获客成本、最易让利润消失的变量。

## 第八步：价格带

回答：顾客在哪个区间购买，你在哪个区间能同时满足需求与利润。

记录：常规可得价、运费、优惠券及条件、会员/订阅价、套装数量、规格与单位价格。单件/两件/四件装同时比每套价和每件价。按价格区间统计商品数、估算销量、估算销售额——**链接最多的价格带不一定是销量最多的**。不能用促销期高销量 × 促销前高价算收入。父体覆盖多价位且只有父体总销量时，不能把销量全放进一个子体的价格带。

**输出**：各价格带需求分布、对应配置、建议试售价、该价格成立的条件。

## 第九步：类目平均评分

回答：顾客对现有商品是否满意，不满意部分能否以可控成本改善。

看：显示星级均值、中位数、评分分布、各商品评价数、近期低星问题、必要时销量加权显示星级 = Σ(显示星级×估算销量) ÷ Σ估算销量（研究者构造指标；Amazon 页面星级由模型算，不是简单均值）。无评分 = 缺失不是 0。
低分原因：尺寸适配不清、包装运损、安装复杂、材料结构缺陷、场景不匹配、期待难实现。「类目评分低」只提示调查，不直接证明机会。

**输出**：评分分布、主要低星主题、可改进问题、难以消除的限制、改善成本。

## 第十步：逐个拆解 Top20

| 字段组 | 内容 |
|---|---|
| 商品身份 | ASIN、产品族、品牌、销售方、规格 |
| 需求定位 | 目标顾客、场景、任务、购买理由 |
| 产品配置 | 尺寸、材质、结构、容量、配件、包装 |
| 经营表现 | 正常价、促销价、销量估算、评价、供货 |
| 页面表达 | 主图、尺寸说明、视频、安装指引、承诺 |
| 好评内容 | 顾客认可的优点与基本要求 |
| 差评内容 | 问题、严重程度、涉及规格、出现时间 |
| 改进可行性 | 方案、成本、打样难度、运输影响、验证方式 |

评论抽样记录时间范围、数量、筛选规则。「某问题在 100 条抽样中出现 20 次」只能说「占已采样评价 20%」，不能说「20% 买家有此问题」。
每个机会方案 7 项：服务哪类顾客 / 解决什么问题 / 跨竞品证据 / 产品或说明如何修改 / 增加多少成本 / 为何能支持拟定售价 / 怎样验证。需要改结构则打样，新的成本尺寸重量返回第七步重算。

**输出**：Top20 逐品档案、跨竞品问题矩阵、1–3 个有证据的改进方案。

## 第十一步：类目退货率

回答：卖出的商品最终保留多少收入，退货消耗多少利润和资金。

优先同站点、同类别、同规格、可核实期间的数据（Product Opportunity Explorer 有退货洞察，但不保证每站点每类目都有同口径数字）。
自有数据：单位退货率 = 某发货批次充分观察后实际退回件数 ÷ 该批次已发货件数（不能「本月退货 ÷ 本月发货」）。
区分：退货率 / 退款率 / 取消 / 换货补发 / 退货原因占比 / 差评率。Keepa returnRate 是等级（1 低、2 高、null 不可得），不是百分比。

退货计入利润（虚构，同币种）：售价 100、到仓 30、履约 10、平台费 15、每单广告 12、全额退款概率 10%、退货处理费 5、可退平台费 12、可恢复净值 24。
不退货订单：100−30−10−15−12 = 33。
退货订单：0−30−10−(15−12)−12−5+24 = −36。
每单预期贡献：90%×33 + 10%×(−36) = 26.1；预期保留收入 100×90% = 90；贡献率 26.1÷90 = 29%。
24 是预计可恢复价值不是到账现金；收入已扣退款就不能再扣一次。

**输出**：退货数据口径、退货原因、损失情景、返回第七步后的修正利润。

## 第十二步：用 Keepa 校验单品真实性（历史一致性核验）

看近 90 天、365 天及更长；季节品跨年比。

| 方向 | 重点 |
|---|---|
| 商品身份 | 站点、ASIN、规格、变体、排名类目是否变化 |
| 价格 | 好销量是否依赖大幅降价，现价能否代表长期价 |
| 排名 | 是否持续、是否只在促销期改善 |
| 供货 | 是否缺货、是否只有自营缺货 |
| 竞争 | 卖家数、自营参与、Buy Box 归属变化 |
| 评价 | 数量变化是否与变体共享或商品变化有关 |
| 数据一致性 | 外部销量估算与历史信号是否重大矛盾 |

monthlySold 是「过去一个月购买 100+/1000+」的区间下限，缺值 ≠ 零销量。salesRankDrops30 是 30 天排名下降次数，不是 30 天销量。
结论四选一：历史表现一致 / 存在异常但可解释 / 证据不足 / 存在重大矛盾需排除。

**输出**：异常日期、相关信号、可能原因、待补证据；不能只凭一张曲线贴造假标签。

## 第十三步：规避高频数据陷阱

| 常见陷阱 | 正确处理 |
|---|---|
| 搜索次数当买家人数 | 保留查询次数定义 |
| 广告位当自然位 | 分别标记 |
| 父体销量重复分给子体 | 按层级去重 |
| 累计评价÷月销叫留评率 | 只作描述比值 |
| Top20 占比写成全类目份额 | 明确样本边界 |
| 促销销量搭配正常高价 | 同一价格与销量情景 |
| 旺季单月预测全年 | 检查完整季节周期 |
| FBA 当自营 | 区分销售方和履约方 |
| 差评/退货等级当退货率 | 检查分母、定义、值域 |
| 「1000+」当精确 1000 | 保留门槛性质 |
| 缺失填 0 | 用未知或不可计算 |
| 多工具接近视为独立验证 | 检查是否同一底层数据 |
| 每天的近 30 天销量相加 | 滚动窗口重叠禁止累加 |
| 只看成功链接 | 补看低销量、新进入、退出商品 |
| 只组合最乐观参数 | 同时列基准与不利情景 |
| 订单贡献为正就认为现金充足 | 另算采购、物流、广告、回款占用 |

还要关注：平台规则变化（如 2026 年 Amazon 调整变体评论共享，评价突增减先查变体与平台调整）；高频采样假象（每小时看一次不是每小时一份独立证据，固定截止日与复核频率）。

**输出**：仍未解决的数据矛盾、关键缺失、情景敏感性、证据完整度。

## 最终交付

| 输出项目 | 必须回答 |
|---|---|
| 目标顾客 | 卖给谁，什么场景 |
| 需求依据 | 哪些关键词和销量证据 |
| 进入位置 | 哪个细分需求与价格带 |
| 产品方案 | 改善什么，怎样验证 |
| 收益模型 | 目标售价、完整成本、广告退货后贡献 |
| 数据可信度 | 哪些是真实记录、估算、假设、未知 |
| 测试计划 | 首批数量、预算、观察周期、补货前提 |
| 退出条件 | 什么情况停止投入或调整 |

最终决定三选一：
- **优先小批量验证**：需求、竞争位置、产品方案有依据，保守情景下仍满足经营约束。
- **继续观察并补证**：有可检验机会，但价格、成本、退货或历史数据有重要缺口。
- **暂不进入**：需求、差异化、成本或资金约束难以同时满足。

首批采购量同时受需求证据、MOQ、可售窗口、补货周期、最大可承受损失约束。不能照头部月销下单，不能让综合分数掩盖关键数据缺失。
