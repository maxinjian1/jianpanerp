# ANET ERP 需求：开店记录、Amazon 商品资料与图片（2026-11-25）

提出：电商会话。实现：ERP 会话。
用户原话：「开店记录这也放在erp系统里」「Amazon图片及产品信息保存在erp」。

## A. 开店记录（出店記録）

目的：用户在 ERP 里一眼看到「哪些平台已经开店、哪些在审核、哪些卡在谁手里、下一步是什么」，不用再翻进度表和聊天记录。

### A-1. 文件 ⑧ `store_openings.csv`（一行 = 一个平台）

UTF-8 带 BOM。唯一键：`platform_code`。生成器 `tools/erp-bridge/store_openings.py`。

| 列 | 必填 | 规则 |
|---|---|---|
| `platform_code` | 是 | 平台编号，例 `tiktok`、`yahoo-shopping` |
| `platform_name` | 是 | 平台名 |
| `shop_name` | 否 | 店铺名 |
| `shop_url` | 否 | 店铺前台地址，可点开（新标签） |
| `admin_url` | 否 | 后台或申请页入口，可点开（新标签） |
| `store_account` | 否 | 店铺账号（不是密码）。文件里**没有也不会有**密码、验证码、信用卡、银行账号 |
| `status` | 是 | `open` 营业中 / `review` 审核中 / `submitted` 已提交等联系 / `returned` 被退回需补件 / `drafting` 填写中未提交 / `rejected` 被驳回 / `not_accepting` 平台暂不受理 / `not_started` 未开始 |
| `status_date` | 是 | 这个状态是哪一天看到的 `YYYY-MM-DD` |
| `verified` | 是 | `confirmed` 在页面上看到 / `user_reported` 用户口头告知 / `unverified` 取自进度表、未核实 |
| `basis` | 否 | 依据，原样文字 |
| `next_action` | 否 | 下一步 |
| `next_owner` | 是 | 下一步在谁手里：`user` / `ai` / `platform` / `none` |
| `documents_needed` | 否 | 还缺的证明文件 |
| `linked_channel` | 否 | 已在 ERP 的販売チャネル 编号（`rakuten-main`、`qoo10-main`）。空 = ERP 里还没有这个渠道，不报错 |
| `note` | 否 | 备注 |

### A-2. 页面

1. **出店記録 一览**（菜单放在販売チャネル 附近）：列 = 平台、店铺名、状态、状态日、核实情况、下一步、谁来做、缺的文件、链接（前台 / 后台）。默认按「下一步在用户手里的」排最前。
2. 状态没有核实的（`user_reported`、`unverified`）要看得出来，不能和 `confirmed` 显示成一样。
3. 用户可在页面上写一行メモ；读入文件不覆盖メモ。
4. **变更记录**：读入时某个平台的状态、状态日、下一步变了，ERP 记下「哪天从什么变成什么」，在该平台的详情里能看到时间线。这样「开店记录」会随每次读入自己积累。
5. 有 `linked_channel` 的，能点到对应的販売チャネル。

### A-3. 验收标准

1. 读入 15 行：open 4、review 1、submitted 1、drafting 5、rejected 1、not_accepting 2、not_started 1。
2. 核实情况：confirmed 6、user_reported 1、unverified 8，页面上三种能区分。
3. 同一文件读两次，第二次全部「没有变化」，不产生变更记录。
4. 把一行的 status 改掉再读入，时间线多一条；メモ还在。
5. 販売チャネル、商品、库存、订单的数量读入前后不变。

### A-4. 不做

ERP 不登录各平台、不替用户提交申请、不保存任何密码或证件文件。

## B. Amazon 商品资料与图片（商品ページ資料）

目的：把 Amazon 商品页上的标题、五点、说明、图片存进 ERP，成为可查的底稿（以后换品牌、做 A+、搬到别的平台时用），不再只躺在一台电脑的文件夹里。

### B-0. 这批数据是什么（如实说明）

- 来源是 **2026-10-17〜18 抓的公开商品页存档**，1,415 个 ASIN（另有 32 个当时没取到页面，不在文件里）。这是当时页面的样子，**不是今天的**。
- 11-12 之后新建的 SALONCARE 链接（约 1,068 个子商品）和之后换过的图**不在这批里**，要另行取得后再出文件。
- 857 个 ASIN 页面上当时没显示价格（多为缺货），`price_shown` 留空。
- 这批是「页面资料」，不是商品主数据：不新建商品、不新建 SKU、不动库存。Amazon 的商品/规格/对照（文件 ①②）我另外出。

### B-1. 文件 ⑨ `listing_content.csv`（一行 = 一个商品页）

UTF-8 带 BOM。唯一键：(`channel_code`, `parent_key`)。生成器 `tools/erp-bridge/amazon-content.py`。说明栏里有换行（已按 CSV 规则加引号）。

| 列 | 规则 |
|---|---|
| `channel_code` | `amazon-main`（ERP 里还没有这个渠道，请随这批建：platform=amazon，名称 Amazon.co.jp） |
| `parent_key` | ASIN |
| `seller_skus` | 该 ASIN 下的出品者 SKU，分号分隔（10-18 出品レポート；共 1,445 个）。只作参考文字 |
| `title` | 商品名 |
| `bullet_1`〜`bullet_6` | 五点，空 = 页面上没有 |
| `description` | 商品说明，140 行为空 |
| `price_shown` | 页面显示价（円，整数）。空 = 当时没显示，不是 0 |
| `rating_text`、`review_count_text` | 原样文字，例「5つ星のうち3.7」「(56)」。不要转数字 |
| `first_available` | 开始销售日，原样文字 |
| `rank_text` | 排名，原样文字 |
| `package_size` | 包装尺寸，原样文字 |
| `sizes`、`colors` | 页面上的规格选项名（这批全空） |
| `image_count` | 图片张数 |
| `fetched_at` | 取得时间（页面资料的日期，页面上要显示） |
| `source` | 来源说明 |

### B-2. 文件 ⑩ `listing_images.csv`（一行 = 一张图）＋图片文件

唯一键：(`channel_code`, `parent_key`, `position`)。

| 列 | 规则 |
|---|---|
| `position` | 在商品页上的顺序，1 = 主图 |
| `source_url` | Amazon 上的原图地址 |
| `file` | 图片文件的相对路径，根目录 = `C:\Users\maxinjian\source\jianpanerp`，例 `tools/amazon-listing/out/opt/<ASIN>/images/01.jpg` |
| `bytes`、`sha256` | 文件大小与校验值 |

- 9,317 行；同一张图被多个颜色/尺码共用，**按 sha256 去重后是 2,264 个文件、约 111 MB**。请按校验值只存一份。
- **图片文件要存进 ERP 自己的存储**（和附件一样随备份走），不要只存链接或只指向我这边的文件夹：Amazon 换图后原地址会失效，我这边的文件夹也不保证一直在。
- 读入方式请你定（例：给一个本机文件夹路径由 ERP 复制进去，或打包上传）。定好告诉我，我按那个方式交付。

### B-3. 页面

1. 商品页资料一览：可按标题、ASIN、SKU 搜索；每行显示主图缩略、标题、价格、图片张数、取得日。
2. 详情：标题、五点、说明原文，图片按顺序排开可放大，能看到取得日和「这是存档，不是现在的页面」的提示。
3. 以后同一个 ASIN 再读入新日期的资料时，**旧的不要丢**：保留为历史版本（至少能看到上一版的文字和图）。换品牌前后的对比就靠这个。
4. 以后 Amazon 的对照（文件 ②）进来后，从商品页能点到这份资料；现在对不上的照常保存。

### B-4. 验收标准

1. 读入页面资料 1,415 行、图片 9,317 行；存储里图片文件 2,264 个。
2. `price_shown` 为空的 857 行显示「未確認」，不显示 0。
3. 抽查 `B07SC2S7PJ`：标题「SALON CARE シャンプー＆コンディショナー＆ボディソープ…」，价格 2,390，图 6 张，取得日 2026-10-17。
4. 同一文件读两次，第二次全部「没有变化」，图片不重复存。
5. 商品数、SKU 数、库存、订单读入前后不变。

### B-5. 不做

ERP 不去抓 Amazon 页面、不改 Amazon 上的内容；评价正文不保存。
