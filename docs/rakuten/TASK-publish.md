# 任务：斑马 ERP 乐天V2 草稿箱 → 补类目 → 发布到乐天（用户 2026-10-21 已确认）

用户决定：
- **价格不改**：用草稿箱里现有的售价（`StandardPrice`，约为批发价 ×1.39）。参考价（二重価格）保持 0，不设。
- **类目由我们选**：乐天平台类目（ジャンル）按商品名自动选；店铺类目用 anetmc 的 8 大类（见下）。
- **没上架的全部上架**，只跳过 **帽子 4 件 + 狗窝 6 件**（`banma-draft-list.md` 的「跳过」行，用户自己手动上）。猫窝/猫笼/头盔内衬帽 5 件也由我们上。
- 库存、图片、标题、规格保持草稿箱原样（只修下面列出的错误）。

## 规则（必须遵守）

1. 只在**用户本人已登录**的 Chrome（斑马 ERP）里操作。不输入任何账号密码，不读密码。遇到登录页、验证码、付款、协议同意画面 → 停下告诉用户。
2. 不改价格、库存、图片。不删除任何商品。不动 Amazon 换图（已暂停）。
3. 每一步写日志：`docs/rakuten/publish-log.csv`（时间、SPU、管理编号、选的平台类目 ID/名称、店铺类目、动作、结果、错误信息）。
4. **先试 3 件**：选 3 件不同大类的商品，补类目 → 保存 → 发布 → 在「发布成功 / 发布失败」标签页确认结果，并在乐天店铺页面（RMS 或店铺前台）确认能看到、价格正确。3 件都成功才继续批量。
5. 批量时每批 ≤ 50 件；失败率超过 2%（或连续 5 件失败）就停下，把失败原因汇总给用户，不要硬跑。
6. 斑马 ERP 是第三方系统：请求之间留间隔（≥1 秒），不要并发轰炸接口。
