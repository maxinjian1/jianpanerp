# Amazon 広告 SOP — 日本站・SARADEMUNT 専用

目的：**流量ゼロの商品に最初の流量を入れ、売れる商品・検索語を見つけて利益の出る範囲で伸ばす**。
現状（`docs/amazon-audit-report.md`、2026-10-18）：1,415 ASIN 中 1,052 件が 90 日流量ゼロ、87 件は流量ありで注文ゼロ、276 件に注文あり。

## 鉄則

1. **お金を使う操作は承認制**：キャンペーン作成・日予算・入札・有効化/停止の変更は、計画（`tools/amazon-ads/out/plan-YYYYMMDD.json` と中文サマリ）を用户に見せて承認を得てから。承認されていない変更はしない。日予算の合計上限は用户が決めた額を超えない。
2. **広告より先に商品ページ**：流量があるのに注文ゼロ（87 件）は広告を足す前に画像・タイトル・価格を直す（amazon-visual-sop / optimize.mjs）。ページが弱いまま広告を出すとお金が消えるだけ。
3. **損益ラインは価格式から**：`tools/amazon-listing/build-inventory-file.mjs` の `amazonPrice()` は広告費 5%（`AD_RATE`）と最低利益率 10%（`MIN_MARGIN`）を見込んでいる。
   - 目標 ACOS ≈ **5%**（価格に織り込み済み）
   - 損益分岐 ACOS ≈ **15% 前後**（5% + 最低利益率 10%。商品ごとに `pricing.tsv` の profitEx から正確に計算する）
   - 立ち上げ期（最初の 2 週間・データ集め）は損益分岐まで許容、それ以降は目標に寄せる
4. **規約**：他社ブランド名をキーワードに入れるのは可能だが、商品ページ・広告文に他社名は書かない。IP 商品（W杯/日本代表/キャラクター等）は広告しない。
5. **Seller Central / 広告コンソール**のログイン・OTP・CAPTCHA・支払い設定は触らない。レポート取得は読み取りのみ（API 化するまでは用户が CSV をダウンロード → `tools/amazon-ads/in/`）。

## 対象の選び方（優先順）

1. 注文実績あり（276 件）→ 伸ばす：マニュアル（完全一致・フレーズ一致）を中心に。
2. 新しく A 案画像＋出品データを作った商品（`amazon-ready`）で、`check.pass` 済み・在庫あり・粗利が出るもの → オートで検索語を集める。
3. 90 日流量ゼロ → 少額オートでテスト。2 週間でクリックが付かないものは商品ページ・カテゴリ（browse node）を見直す。
4. 流量あり注文ゼロ → **広告対象外**（先にページ改善）。

## キャンペーン構成（スポンサープロダクト）

商品グループ（同じ客群・価格帯、例：箱包、収納、寝具）ごとに：
- **Auto**：日予算 小、入札はカテゴリ推奨の下限〜中央。目的は検索語の発見。
- **Manual-Exact**：Auto で注文の出た検索語、関键词调研で決めた核心語。
- **Manual-Phrase**：核心語の周辺を広く。
- **商品ターゲティング**：自社の類似 ASIN・補完商品（他社 ASIN は価格・評価で勝てるものだけ）。

命名：`SP_<グループ>_<Auto|Exact|Phrase|ASIN>_<YYYYMM>`。

## 毎週の運用（検索語レポート → 判断はコード、変更は承認）

| 条件（直近 14 日） | アクション案 |
|---|---|
| クリック ≥ 10、注文 0 | その検索語を Auto/Phrase で**除外**（完全一致除外） |
| 注文 ≥ 2、ACOS ≤ 目標 | Exact に**昇格**、入札 +10〜20% |
| ACOS > 損益分岐 | 入札 −15〜25%、改善しなければ停止 |
| インプレッションほぼ 0 | 入札をカテゴリ推奨の中央へ、またはキーワード見直し |
| 予算消化 100% かつ ACOS ≤ 目標 | 日予算の増額を**提案** |

関键词：商品名から型番・誇張語を除いた核心語 2〜4 個（visual.mjs `compete` の keywords と同じ考え方）＋Amazon 検索サジェスト＋Auto の実績語。日本語の表記ゆれ（カタカナ/ひらがな/漢字、全角/半角）は別キーワードとして扱う。

## 出力

```
tools/amazon-ads/
  in/            # 用户がダウンロードした検索語レポート・キャンペーンレポート（CSV、git に入れない）
  out/plan-YYYYMMDD.json   # 提案：新規キャンペーン、除外、昇格、入札・予算変更（各行に理由と数字）
  out/plan-YYYYMMDD.md     # 中文サマリ（用户が承認する用）
  out/applied-YYYYMMDD.json # 承認後に実際に反映した内容（元の値を残す＝戻せる）
```
