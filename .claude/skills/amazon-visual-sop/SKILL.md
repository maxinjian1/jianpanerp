# Amazon 视觉 SOP（上架前の画像処理）

目的は「きれいな画像」ではなく **用户が一目で『なぜこれを買う価値があるか』を理解できる画像**。
きれいなだけの画像・卖点を詰め込んだだけの画像は点击率も转化率も上がらない。

## 鉄則（毎回守る）

1. **画像の中の約束はすべて商品事実で裏づける。** 寸法・重量・素材・容量・耐荷重・枚数などは、批发商の商品データ（日文站 view 0 の説明・SKU・画像に写った表記）か実測値にあるものだけ。無い数字は書かない・作らない（「約」で誤魔化さない）。根拠は `brief.json` の `facts[]` に出典付きで残す。
2. **Amazon 主图ルール**：純白背景（RGB 255）、商品のみ、文字・ロゴ・枠・透かし・付属しない小物は禁止、商品が画面の 85% 前後、長辺 1600px 以上（推奨 2000px）、JPEG sRGB。違反すると 100581/100588/100560 で落ちる。主图の A/B は「角度・構図・見せる面・付属品の並べ方」で差をつける（文字では差をつけない）。
3. **副图（2〜7 枚目）**は文字を入れてよいが「AI は絵だけ、文字はコード」：AI に日本語を描かせない。文字は `tools/brand-assets/product-cards.mjs` の Chromium テンプレートで Noto Sans JP を描画する。
4. **合規**：最強・No.1・絶対・日本一・医療効果（治る/痩せる/バストアップ/UV カット率の断言）・他社ブランド名・W杯/日本代表など IP は使わない。景品表示法・薬機法に触れる表現は削る。
5. **AI 画像生成は商用可のモデルだけ**（Qwen-Image-Edit など Apache-2.0）。FLUX Fill dev は非商用ライセンスなので量産に使わない。商品そのものの形・色・ロゴは生成で変えない（原图の商品ピクセルを貼り戻す。`tools/comfy/compose.py`）。
6. **公開は承認制**：作った画像は anetmc.com の **審査用 DRAFT 商品**にだけ載せる。現行の公開商品の画像は変えない。ユーザーが承認したものだけ Amazon へ（`tools/product-images/approved.txt` / `amazon-approved` タグのルールと同じ）。

## 4 ステップ

### 第一步：找准对标竞品
- 商品の核心キーワード（日本語）を 2〜4 個決める（商品名から型番・修飾語を除いたもの + Amazon 検索サジェスト）。
- `tools/amazon-research/research.mjs collect/detail` で ベストセラー・新着・急上昇 と検索結果上位を取る。
- **同版型・同价位（自社想定売価 ±30%）・同客群** で 5〜8 件に絞る。BSR・レビュー数・評価・発売日を記録。
- 出力：`brief.json.competitors[]`（asin, title, price, rating, reviews, bsr, 選んだ理由）。

### 第二步：拆解竞品图片，找出表达空缺
- 各竞品の主图 + 副图を取得し、6kpro 視覚モデルで 1 枚ずつ分類：角度（正面/斜め45°/真上/側面/背面）、光（フラット/サイド光/逆光）、背景、写っている情報（素材感/構造/サイズ/使用場面/付属品/比較/保証）。
- 表にして **「みんな同じ」所と「誰も見せていない」所** を出す。例：全員が正面フラット光 → 斜め45°+サイド光で素材の質感と立体構造を見せる。全員がサイズを文字だけ → 手や A4 との比較写真で見せる。
- 出力：`brief.json.gaps[]`（観察、自社でどう差をつけるか、使う原图）。

### 第三步：用评论确定视觉重点
- 竞品の **差評（★1〜3）→ 顧慮**、**好評（★4〜5）→ 需求** を抽出し、頻度順に並べる。
  - 例（女士斜挎包）：差評「バックルが弱い」「内側が色落ち」「思ったより入らない」→ 細部アップ・耐荷重テスト・実際に物を入れた装載実拍で答える。好評「軽い」「何にでも合う」→ 通勤・旅行シーンで見せる。
- **自社商品の事実で答えられる顧慮だけ** 画像にする。答えられない顧慮（データが無い）は画像にしない、`brief.json.unanswered[]` に残して仕入れ先確認リストへ。
- 出力：`brief.json.concerns[]` / `needs[]`（内容、件数、出典 ASIN、どの画像で答えるか、根拠 fact）。

### 第四步：做两套方案测试
- **A 案 / B 案**の 2 セットを作る。変えるのは 1 軸ずつ：
  - 主图：構図（例 A=斜め45°単体 / B=正面+付属品並べ）→ 点击率で判定。
  - 副图：卖点の順番（例 A=顧慮解消が先 / B=使用シーンが先）→ 转化率で判定。
- 判定データ：Amazon「Manage Your Experiments」（ブランド登録が必要）が使えればそれ。使えない場合は 2 週間ずつ交互に掲載し、ビジネスレポートのセッション・ユニットセッション率（CVR）、広告のインプレッション/CTR で比べる。結果は `brief.json.tests[]` に記録し、勝ち案を残す。

## 1 商品の成果物

```
tools/amazon-visual/out/<handle>/
  brief.json        # competitors / gaps / concerns / needs / facts / unanswered / plan(A,B) / tests
  a/01-main.jpg …   # A 案 7 枚（01 主图は純白）
  b/01-main.jpg …   # B 案 7 枚
  preview.jpg       # A/B 並べた联络表（審査用）
```

副图の標準構成（7 枚、順番は A/B で入れ替える）：
1. 主图（純白・文字なし）
2. 一目でわかる価値（最大の需求 1 つ＋商品）
3. 顧慮への回答①（細部アップ/テスト）
4. 顧慮への回答②（容量・装載実拍/サイズ比較）
5. 寸法図（事実の数字のみ）
6. 使用シーン（客群に合わせる）
7. セット内容・安心（付属品、保証、配送）

## 審査と出品

1. 2 案ができたら anetmc.com に **DRAFT の審査用商品**（タグ `amazon-review`、タイトル先頭【Amazon審査】、A 案の画像、説明に brief の要約と B 案画像）を作る。公開商品には触れない。
2. ユーザーが Shopify 管理画面で確認し、採用案をタグ `amazon-approved-a` または `amazon-approved-b` で承認（やり直しは `amazon-redo` + メモ）。
3. 承認タグが付いたものだけ、Windows の出品処理が Amazon に出品（`tools/amazon-listing/`、ブランド SARADEMUNT、出品者出荷、送料無料パターン、価格は `amazonPrice()`）し、`amazon-listed` タグに替える。
4. Seller Central のパスワード/OTP/CAPTCHA/支払い/規約同意の画面は触らない（止めてユーザーに渡す）。
