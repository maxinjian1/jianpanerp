# Amazon.co.jp 選品 SOP — 13 步 AI 執行版

原文（手順・計算式・陥阱表・最終交付）は **`docs/amazon-sourcing/选品全流程-AI执行版.md`** にある。この skill はそれを**当社環境でどう実行するか**だけを書く。手順の中身で迷ったら原文を読む。

## 鉄則（原文の硬性要求 ＋ 当社ルール）

1. **数据没有就写「未知」、估算就标「估算」、不编造数字。** 表を埋めるために値を作らない。欠損は 0 ではなく「未知/不可計算」。
2. 每个数字必须带：**来源・口径・时间窗口・商品层级（子ASIN/产品族/合计）**。来源のない数字は結論に使わない。
3. 結論は三択のみ：**优先小批量验证 / 继续观察并补证 / 暂不进入**。綜合スコアで欠損を隠さない。
4. **お金が動く操作（1688 発注、FBA 納品、広告作成）はしない**。この skill の出口は「結論＋首批数量の提案」まで。発注は用户承認後に別途。
5. 6kpro は**夜間（北京 20:00〜10:00）だけ批量使用**、昼は零星的な対話のみ（CLAUDE.md）。Top20 の評論拆解など LLM 批量処理は夜間ジョブに回す。
6. Amazon 公開ページの取得は Windows の CDP ブラウザ（`tools/amazon-research/research.mjs` と同じ 9222）。CAPTCHA が出たら止める、しつこく再試行しない。Seller Central のログイン・OTP は触らない。

## 手順

1. **口径表を先に埋める**（原文「开始之前」の 7 項目）。目标市场は常に Amazon.co.jp。これが埋まらないうちに数字を集めない。
2. 第 1〜6 步＝**市场侧**：`research.mjs collect --cat <类目>` → `detail` で Top20 候補を取り、相关性筛选と产品族去重をしてから Top20 を確定。除外した商品と理由を残す。
3. 第 7〜8 步＝**经济侧**：仕入候補（kjyf / 1688）の見積を取り、三層の贡献を計算。基准・不利（售价 −10%、广告 +30%、退货 +5pt）・楽観の 3 情景を必ず並べる。
4. 第 9〜10 步＝**产品侧**：評論拆解は夜間ジョブ（`tools/night/jobs.txt` に 1 行追加、`--window 20-10`）。改进方案は 7 項目テンプレで 1〜3 個。構造変更があれば 7 步へ戻して再計算。
5. 第 11〜12 步＝**修正と核验**：退货を 7 步に反映。Keepa で異常日付を列挙、四択で結論。
6. 第 13 步：陷阱表を上から順に自己点検し、該当したものは本文を直す。
7. **最終交付**を書く（原文の 8 項目＋三択結論＋首批数量の制約式）。

## やらないこと

- Top20 中位数をそのまま新品の予測销量にしない。首批数量は「需求证据・MOQ・可售窗口・补货周期・最大可承受损失」の最小値で提案する。
- 累计评价÷月销を「留评率」と呼ばない。CR3 を「市场份额」と呼ばない。FBA を自営と数えない。「1000+」を 1000 と書かない。
- 6kpro（または他の LLM）に数字を**生成**させない。LLM の役割は評論の主題抽出と文章化だけ。計算はコードか手計算で、式を report に残す。
- 1688 への問い合わせ送信は既存ルール（≥60 秒間隔、日 ≤20 通、approved=true のみ）に従い、選品結論が出る前には送らない。
